**公開日:** 2026年8月7日

Microsoft は、TypeScript のネイティブ言語サービスにワークスペースシンボル検索のスコープを追加する変更をマージしました。

## 変更点

新しい `workspaceSymbols.scope` 設定には 2 つの値があります。`allOpenProjects` がデフォルトで、開いているすべてのプロジェクトからシンボルを検索します。`currentProject` は、指定されたドキュメントを含むプロジェクトに検索を制限します。

ネイティブ VS Code 拡張機能は、対応する TypeScript または JavaScript のドキュメントを `workspace/symbol` リクエストに追加するようになりました。アクティブなドキュメントを優先し、それがない場合は、開いている対応ドキュメントを使用します。言語サービスは、`workspaceSymbols.scope` が `currentProject` の場合にのみそのドキュメントを使用します。それ以外の場合は、開いているすべてのプロジェクトを対象とする検索を維持します。

## 重要である理由

同じような名前のシンボルを持つ複数のプロジェクトがワークスペースに含まれている場合、`currentProject` を使用すると、結果を関連するプロジェクトに限定できます。デフォルトでは既存の動作が維持されるため、この変更はオプトインです。

## 利用可能性

この変更は、TypeScript 7.0 のリリース後に TypeScript のネイティブコードベースへマージされました。この設定を含む安定版の npm バージョンは出典に記載されていないため、利用する前に、インストール済みバージョンのリリースノートを確認してください。
